# OceanCast 公司官网首版设计

## 目标

把已下载的 YourNextStore 模板调整为南京海潮人工智能科技有限公司（OceanCast）的中文品牌官网。首版突出 AI 创作服务和作品案例，保留 AI 需求助手用于了解需求和推荐服务，并通过企业微信承接人工咨询与售后。价格尚未确定，因此所有服务使用“咨询报价”，首版不开放在线支付。运行需要配置 YourNextStore API；AI 助手还需要在后台启用聊天功能。

## 已确认的需求

- 品牌：OceanCast；公司中文名：南京海潮人工智能科技有限公司。
- 服务：AI 短剧、AI 海报、AI PPT 与定制 AI 创作。
- 视觉：深海蓝、海青色、充足留白、大幅作品图；海浪只作轻微装饰，避免钓鱼品牌观感。
- 新增案例：用户刚提供的水彩手作饰品场景图，作为作品展示中的第一张案例图。
- 客服：单独设置“客服咨询”板块，使用用户之前提供的企业微信二维码，引导客户扫码联系人工客服。
- 价格：待定，显示“咨询报价”。
- 部署计划：修改完成后先把源码放到 GitHub；网站托管方式之后再定。
- 个人介绍 HTML：不直接发布其中的姓名、学校、个人联系方式、证书等信息。其他项目只有在用户确认可公开后才能作为公司案例。

## 实现路径与取舍

1. **推荐：改造现有模板为作品展示与人工询单站。** 保留 Next.js 与模板的商店后台和 AI 助手，首页使用本地内容展示服务、案例和客服二维码，不依赖商品清单，也不开放结账。仍需有效 YourNextStore API key 才能运行模板；聊天还需后台启用和有效订阅。适合当前价格待定、咨询由人工承接的阶段。
2. **保留完整电商。** 继续使用模板的商品、购物车和结账能力；需要配置 YourNextStore API、正式产品与价格及支付方式。当前缺少这些信息，因此不作为首版。
3. **另建独立静态站。** 可减少电商后端依赖，但会丢弃已经下载的模板并增加重复工作，不推荐。

首版采用路径 1。YourNextStore 模板的共享布局读取商店元数据时就依赖 `YNS_API_KEY`，因此完整预览和运行前必须配置有效 API key；服务卡片本身使用静态内容，不依赖产品清单，也不创建虚构价格或结账按钮。AI 需求助手沿用模板已有的 StoreChat 能力，需要有效 API key、YNS 后台启用聊天工具和有效订阅后才能真实对话。密钥只放在私有环境变量中，不提交到 GitHub。客服二维码始终可独立使用，不展示假 AI 回复。

## 首页结构

1. **导航与首屏：** 显示 OceanCast 标识、中文公司名和服务/作品/客服导航。首屏用简洁文案表达“AI 创作服务”，搭配深海蓝和海青色视觉。海洋元素控制在细线、柔和渐变或微弱波纹。
2. **服务展示：** 四项服务卡片：AI 短剧、AI 海报、AI PPT、定制创作。每张卡片可进入“咨询报价”或跳转到客服咨询。
3. **作品展示：** 使用大图卡片展示新上传的水彩手作饰品场景。暂用标题“手作饰品主题视觉”与客观描述，不声称客户名称、商业成果或未确认的制作流程。保留扩展更多案例的结构。
4. **客服咨询：** 独立板块标题为“客服咨询”，文案说明扫码添加企业微信后可沟通需求与售后。展示已有企业微信二维码，确保二维码及其留白区域完整可扫；不将二维码伪装成网页内即时聊天。
5. **AI 需求助手：** 保留模板的 StoreChat 入口，用于客户描述需求和获得服务推荐；无法解决、需要下单或售后时，引导客户使用“客服咨询”添加企业微信。
6. **页脚：** 显示公司中文名和 OceanCast 品牌名，保持简洁。

## 视觉与交互细节

- 以白色或浅色背景为主，深海蓝承担标题和重点文字，海青色用于按钮、标签和少量强调。
- 作品图按纵向画幅呈现；桌面端与移动端均保留合适的主体比例，不覆盖到重要内容。
- 客服二维码沿用用户提供的原始二维码数据，不重绘、不用生成式工具处理。若用裁切容器突出二维码，必须保留二维码四周完整白色静区；点击可查看完整联系卡片。
- “咨询报价”按钮滚动到客服板块或打开二维码卡片。因为目前只有二维码，没有可验证的企业微信直达 URL，网站的明确动作是“扫码添加企业微信”。
- AI 需求助手依赖 YNS API 和后台聊天配置。未配置时，小助手入口仍显示，点开说明当前未接入，并提供“客服咨询”人工入口；不显示伪造回复。
- 在线下单和更多作品作为后续扩展。

## 首版范围

**包括：** 中文首页、公司品牌介绍、四项 AI 服务、首个作品案例、企业微信客服咨询区、AI 需求助手入口和人工转接路径、响应式排版和咨询报价入口。

**暂不包括：** 商品价格、在线购物车与支付、订单管理、客户账户、在线提交后端、GitHub 推送与网站托管配置、未确认公开权的个人作品/资料。YNS API key 和后台聊天功能配置是运行模板的前置条件，由用户在私有环境中配置，不写入仓库。

## 主要组件边界

- `Hero`：品牌和首屏介绍。
- `Services`：静态服务目录与咨询入口。
- `Portfolio`：案例卡片数据与作品图片。
- `CustomerService`：企业微信二维码、说明和扫码指引。
- `StoreChat`：复用模板现有的 AI 对话能力，并提供转人工的客服入口；依赖 YNS 配置。
- 首页组合以上区块；不要让这些只读展示依赖商品 API。

## 源码与托管

- 当前只准备源码项目，完成修改后再按用户的 GitHub 账号/仓库安排上传。
- 本地运行和模板 AI 对话需要有效 `YNS_API_KEY`；私钥只放在 `.env.local` 或托管平台的私有环境变量中，`.env.local` 不得提交。
- 用户尚未选择网站托管平台。保留 Next.js 服务端能力，不启用 GitHub Pages 静态导出，也不添加特定托管平台的部署流程。
- 后续部署前再确认 GitHub 仓库地址与公开/私有属性，并选择可运行 Next.js 服务端功能的托管环境；若届时选择 GitHub Pages，需要重新评估 AI 助手与服务端功能。

## 失败处理与隐私

- 图片未加载时提供稳定的背景和替代文本，不阻断服务信息。
- 二维码不可用时，保留“客服咨询”文字并提示扫码联系，不伪造联系方式。
- 不复制个人自我介绍中的电话号码、邮箱、学校和证书到公开页面。
- `YNS_API_KEY` 缺失或无效时，模板不能完整运行；部署前提示在私有环境中配置，不提供虚假预览成功状态。密钥不写入前端代码或 Git 提交。企业微信二维码作为用户明确提供、用于客服联系的公开图片素材；不额外编造或展示个人联系方式。

## 验收标准

- 配置有效 YourNextStore API 后，首页展示静态服务卡、案例和客服区；首页不因空产品目录显示错误或虚构产品价格。
- YNS 后台开启 StoreChat 后，AI 助手可引导需求并推荐服务；未开启时小助手说明尚未接入，不返回伪造 AI 回复，并提供企业微信入口。
- 新上传图片出现在“作品展示”，显示比例适配桌面与手机。
- “客服咨询”区展示原企业微信二维码，并有清楚的扫码说明；二维码仍可扫描。
- 服务价格均显示“咨询报价”，没有虚构商品价格、结账或支付承诺。
- 页面维持深海蓝/海青色的 OceanCast 品牌风格，海洋元素克制。
- 源码不绑定到尚未选定的托管平台。
- 公开页面不带入 HTML 中的个人资料。
